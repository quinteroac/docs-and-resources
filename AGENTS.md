# AGENTS.md

## Repository Overview

This repository is a personal knowledge base containing documentation, articles, book summaries, tutorials, guides, and curated resources.

AI agents working in this repository should prioritize accuracy, clarity, consistency, and long-term maintainability.

## Repository Structure

```text
docs-and-resources/
├── README.md
├── AGENTS.md
├── articles/
├── books/
├── tutorials/
├── guides/
└── resources/
```

### Content Categories

- **articles/** — Articles, research notes, technical insights, and summaries of interesting publications.
- **books/** — Book summaries, reading notes, important concepts, and key takeaways.
- **tutorials/** — Step-by-step instructions, practical exercises, and reproducible examples.
- **guides/** — Explanations, best practices, reference documentation, and how-to guides.
- **resources/** — Curated collections of links, tools, libraries, references, and learning materials.

Choose the most appropriate category based on the content's primary purpose.

## General Instructions

1. Write all content in Markdown.
2. Use English by default unless the user requests another language.
3. Preserve technical accuracy and the original meaning of source material.
4. Prefer clear, direct explanations over unnecessary verbosity.
5. Organize information using descriptive headings and logical sections.
6. Use lists, tables, diagrams, and code blocks when they improve readability.
7. Avoid duplicating existing content.
8. Preserve existing documents unless changes are explicitly requested.
9. Never fabricate facts, references, quotations, or technical details.
10. Prioritize useful information over generic introductory text.

## Content Creation

When creating a new document:

1. Identify the subject and purpose.
2. Check whether related content already exists.
3. Select the appropriate directory.
4. Create a descriptive filename using lowercase kebab-case.
5. Structure the document with meaningful Markdown headings.
6. Include practical examples when relevant.
7. Reference original sources whenever possible.
8. Update the relevant index or README if necessary.

### Recommended Document Structure

```markdown
# Document Title

Brief description of the topic.

## Overview

Introduction and essential context.

## Key Concepts

Important definitions, ideas, and explanations.

## Details

Main content organized into relevant sections.

## Examples

Practical examples, commands, or demonstrations.

## Key Takeaways

Summary of the most important points.

## References

- [Source Title](https://example.com)
```

Adapt this structure to the content type. Do not create empty or unnecessary sections.

## Articles

When documenting or summarizing articles:

- Preserve the author's central arguments and conclusions.
- Distinguish factual claims from opinions and interpretations.
- Capture relevant technical details, evidence, and examples.
- Include the original article's title, author, and URL when available.
- Avoid reproducing copyrighted articles in full.
- Prefer original summaries and explanations.

## Books

When creating book summaries:

- Include the book title and author.
- Organize information by chapter or major topic when appropriate.
- Explain important concepts in your own words.
- Highlight useful ideas, examples, and conclusions.
- Distinguish the author's ideas from personal observations.
- Do not invent quotations, page numbers, or chapter references.

## Tutorials

Tutorials should be practical, reproducible, and easy to follow.

Include when relevant:

- Prerequisites and dependencies.
- Required tools and versions.
- Installation and configuration steps.
- Commands and code examples.
- Expected results.
- Common problems and troubleshooting.
- References to official documentation.

Do not claim that commands or examples have been tested unless they were actually executed.

## Guides

Guides should focus on explaining concepts or solving specific problems.

- Start with the problem or objective.
- Explain the recommended approach.
- Include alternatives and trade-offs when relevant.
- Use examples to clarify complex concepts.
- Prefer actionable guidance over abstract descriptions.

## Resources

Resource collections should be curated rather than exhaustive.

For each resource, provide:

- Name.
- Link.
- Brief description.
- Relevant context or use case.

Avoid duplicate, broken, or irrelevant links. Verify availability when browsing tools are accessible.

## Sources and References

Source integrity is essential.

- Prefer official documentation, original publications, academic papers, and primary sources.
- Provide direct links to referenced material.
- Clearly distinguish verified information from assumptions.
- Preserve important context when summarizing.
- Never invent citations or URLs.
- Identify uncertainty when sources are incomplete or conflicting.
- Do not imply that external sources were checked if they were not accessed.

## Markdown Conventions

- Use one H1 heading per document.
- Use H2 and H3 headings for sections and subsections.
- Use fenced code blocks with language identifiers.
- Use relative links for internal repository references.
- Use descriptive link text.
- Keep paragraphs focused and readable.
- Avoid unnecessary HTML.
- Use tables only when they improve comprehension.

### File Naming

Use lowercase kebab-case filenames.

Examples:

```text
articles/attention-mechanisms.md
books/designing-data-intensive-applications.md
tutorials/installing-comfyui.md
guides/git-workflows.md
resources/ai-tools.md
```

## Repository Maintenance

When modifying existing content:

1. Read the relevant document before editing.
2. Preserve accurate and useful information.
3. Correct outdated or misleading statements when supported by evidence.
4. Avoid unnecessary rewrites.
5. Maintain consistent formatting and terminology.
6. Check internal links affected by changes.
7. Update navigation and indexes when appropriate.

Do not reorganize directories, rename files, or delete content without a clear reason or explicit instruction.

## Agent Behavior

AI agents must:

- Follow the user's explicit instructions over repository defaults.
- Make focused changes that address the requested task.
- Ask for clarification when essential information is missing.
- Avoid introducing unsupported assumptions.
- Respect existing content and organizational conventions.
- Report important limitations or unresolved uncertainties.
- Clearly communicate which files were created or modified.
- Avoid unrelated changes.

## Quality Checklist

Before completing a task, verify that:

- [ ] The content is factually accurate to the extent verifiable.
- [ ] The document belongs in the correct directory.
- [ ] The filename follows repository conventions.
- [ ] Headings and formatting are consistent.
- [ ] Sources and references are included when applicable.
- [ ] Code examples are correctly formatted.
- [ ] Internal links are valid.
- [ ] No unnecessary duplication was introduced.
- [ ] The requested task has been fully addressed.

## Guiding Principle

**The goal is not to accumulate information, but to preserve useful, accurate, well-organized knowledge that can be easily retrieved, understood, and reused.**
